# TIAMAT — Recovered Head Roles and Scope

> Archaeological reference. Preserve this document even when implementation changes. Do not silently reinterpret a head as a generic predictor.

## Core principle

TIAMAT's heads are scoped by **topology / transition lineage**. The head name is not merely a strength or risk bucket. Each head occupies a particular legal transition/mechanism seat.

The recovered body constructs state and lineage first. The heads interrogate scoped transitions on top of that body. Visualization/diagnostic outputs must not be promoted into authority without an explicit governance decision.

## Recovered head roles

### H0 — 0→4 lineage

Handles the **0→4 entry lineage**: the low-prior-burden admission path.

It is not a generic low-hazard predictor. Its meaning comes from the 0→4 transition topology.

### H2 — 2→4 lineage

Handles the **2→4 entry lineage**: the intermediate-prior-burden admission path.

It is distinct from H0 because the state immediately preceding admission is different.

### H3 — 3→4 boundary

Handles the **3→4 boundary**: the high-prior-burden / preloaded entry condition.

H3 is a boundary mechanism, not simply a stronger version of H0/H2.

### H4 — 4→4 persistence / release

Handles **4→4 persistence/release**: what happens when the system is already in Stage 4 and remains there or transitions toward release.

It therefore belongs to persistence/release topology rather than initial admission.

### ExitBridge — exit / timing machinery

Provides separate **exit/timing** machinery. It bridges the active state toward release rather than acting as another entry head.

### PriorCarry — prior-state/history carry

Carries **previous-state/history information** across the transition boundary. It preserves the prior burden that makes the different entry paths meaningful.

### T3 — baseline steering

Separate **baseline steering** machinery. It is not one of the scoped 0→4 / 2→4 / 3→4 / 4→4 entry/persistence heads.

### S2 — annotation / diagnostic

**Annotation/diagnostic only.** It is not an authority head.

## What must not be done

- Do not collapse H0/H2/H3 into a single generic predictor.
- Do not route a head solely by hazard magnitude when its historical identity is transition lineage.
- Do not use H3 as a generic "strongest" head.
- Do not turn H4 into an entry detector.
- Do not promote ExitBridge into an entry authority.
- Do not treat PriorCarry as an independent prediction head; its role is historical carry/context.
- Do not promote S2 from diagnostic/annotation status without an explicit governance decision.
- Do not use BVD/DVB visual reference outputs as canonical state or authority merely because they are useful for visualization.

## Historical body / head separation

The recovered historical body is the substrate on which these heads operate:

```text
observations
  → primitive state (SimpleShock / LiveDeficit / RecoveryWeakness)
  → hazard / stage state
  → run + entry lineage
  → episode / age / persistence
  → scoped head mechanisms
  → authority firewall
```

The historical Layer-1 witness panel contains the realized hourly state/outputs needed to replay this separation. The original LiveDeficit generator is a known archaeological gap; its absence does not justify inventing a replacement or changing head scope.
