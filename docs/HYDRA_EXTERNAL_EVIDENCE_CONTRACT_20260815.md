# Hydra External Evidence Contract

## Purpose

Hydra V2 does not require the Layer-1 evidence panel to live in Git. The repository stores the court implementation, integrity rules, and methodology. Evidence is supplied at execution time and is bound to the run by SHA-256.

## Required evidence

- SHA-256: `6f0dc516fdf3313ab27a38d942504d073faccba4067877531b44c219c5e4b31a`
- Rows: `43848`
- Native `3_to_4` starts: `169`
- Target: `Crash72`

## Runtime contract

The manual workflow accepts:

- `evidence_url`: HTTPS URL resolving to the exact evidence CSV;
- `evidence_sha256`: expected SHA-256.

The runner downloads the file, verifies the digest and structural invariants, then runs the Layer-1 causal clearance audit and Hydra V2 against that exact file.

## Governance

The 15-column evidence panel is an evidence artifact, not a causal feature matrix. `Crash72`, `entry_path`, `episode_age_h`, `duration_bucket`, and `episode_type` are quarantined. `hazard_raw`, `hazard_score`, and `hazard_bucket` remain native-state suspect variables until the Hazard audit clears them.

The 10-column projection may be generated by the canonicalizer, but it is not promoted to causal truth merely because obvious hindsight columns were removed.

## Reproducibility identity

A court run is identified by:

`court code SHA + evidence SHA + methodology lock SHA + workflow inputs`

The raw evidence therefore does not need to be committed to Git history.
